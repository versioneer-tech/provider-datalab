# Contribute

Open an issue to discuss a large change before you start work. For a defect,
include the affected version, steps to reproduce it, and the expected result.
Use synthetic data and remove credentials from examples and logs.

Keep pull requests focused. Explain the behavior change and list completed
checks and checks that could not run. Add tests for required behavior, a known
defect, or a material risk. Do not add tests only to increase coverage.
Sign your commits. Maintainers create unsigned release tags with Git after
the release checks pass.

Use the [development instructions](README.md#development) to build and check
changes. Edit composition sources and templates, then regenerate the build.

Contributions use the [Apache-2.0 license](LICENSE). Keep copyright and upstream
notices. No contributor license agreement is required.

Send vulnerability reports through the [security policy](SECURITY.md#report-a-vulnerability),
not a public issue.
